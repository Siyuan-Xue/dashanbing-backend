# Actual analyst screenshots

The homepage now uses a concise HTML/CSS feature illustration in `HeroAnalystPreview`, sharing the video preview's frame and showing existing quick-demo metrics and camera images. It does not fetch screenshot manifests, analyst endpoints or a model provider. The real screenshot workflow below remains available for result-page documentation and visual review; those long-form captures are no longer the homepage artwork.

Prerequisites:

- Start the real backend and frontend using the same cookie origin, e.g. frontend 5183 proxying backend 8011 via `VITE_API_PROXY`
- Configure real GLM access on the backend and run the repository's `scripts/generate_analyst_presets.py` according to its CLI help to save verified reports under `runtime/analyst-presets`
- Supply an authenticated Playwright storage state file outside the repo, e.g. `/private/tmp/analyst-auth.json` (never commit cookies)
- Install the frontend's Playwright Chromium and make a Python with Pillow WebP support available

From `frontend`:

```sh
node scripts/capture-analyst.mjs --base-url http://localhost:5183 --storage-state /private/tmp/analyst-auth.json --python /path/to/python3
```

Optional `--wait-seconds 600` waits for another process to finish generating real reports. The capture tool only performs authenticated reads and does not generate reports. `--output-dir /private/tmp/analyst-previews` supports review before copying the entire output into `frontend/public/assets/previews/analyst`.

The script launches fresh browser contexts with service workers blocked, checks the live `/users/me`, requires `completed`, GLM `verified` provenance and `glm-5.3`, recomputes the current facts hash using the backend's canonical Python JSON, validates anonymous subject labels and evidence citations, and compares the rendered report ID/model/summary with the live response. API writes are blocked. There is no mocked-report override.

Each desktop/mobile × light/dark × zh/en combination produces two native browser screenshot crops, for **16 WebP assets**:

- `main`: the actual video player at its native dimensions
- `analyst`: the complete analyst section, including its title, configuration trigger, entire report, training suggestions and compact follow-up area through the composer, with its native bottom spacing

The result page order is video → overview/timeline/JSON → analyst. The intervening data tabs, account navigation, and task header are outside both independent crops. The real video is paused at six seconds for a stable frame. Both images are captured from the same loaded page without changing or composing report content. All captures use device pixel ratio 2; the homepage chooses the matching mobile sources rather than shrinking desktop text. PNG-to-WebP conversion does not resize or edit content. A layout that has the wrong section order or clips report/follow-up content fails capture. The tool never stitches the report over the intervening data section. The homepage uses the same canvas background as adjacent sections and displays screenshots at their natural aspect ratio, with horizontal padding and no viewport-height cap or partial paragraph crops.

The version 2 manifest records `kind`, locale/theme/viewport, pixel dimensions, `pixel_ratio`, report ID, canonical report hash and facts hash for every image. All 16 must share the same facts hash; each language must share the same report ID and report hash across both crops, both themes and both viewports. The complete matrix is checked before the manifest is published atomically. No account identifiers or credentials are included. Review the crops for readable text and appropriate anonymity before delivering the static assets.

No screenshot assets are generated by frontend unit or mocked E2E tests. Fixture tests cover the 16 metadata/crop variants but are not eligible for public delivery. Without configured GLM access, leave the existing truthful homepage fallback in place. If a verified manifest exists but an asset fails to load, the homepage reports screenshot unavailability instead of implying that the AI configuration is missing.
