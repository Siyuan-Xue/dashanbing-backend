# 管理员使用与账户迁移

管理员和普通用户互斥，登录后分别进入 `/admin` 和工作台。管理员后台只处理运行数据和安全调度，不展示视频、报告正文、聊天、档案目标或训练笔记。

| 页面 | 可以做什么 |
| --- | --- |
| 运行概览 | 查看资源、队列、用量、耗时及错误分类 |
| 账号管理 | 搜索普通账户，启用、停用、强制退出和调整配额 |
| 调度中心 | 暂停或恢复领取，暂缓排队任务，调整优先级，有限重试和补齐报告 |
| 配额与并发 | 在服务器给出的范围内修改默认配置或账户限制 |
| 运维状态 | 只读查看应用版本、数据库版本和服务配置状态 |
| 操作记录 | 查看操作者、对象、原因、前后值和执行结果 |

修改前填写原因并确认。并发调整只影响后续领取，降低上限不会中断正在执行的请求。暂停队列、停用账户也不会终止已经运行的视频或 AI 作业。停用或强制退出会使该账户原有会话和业务密钥失效，启用后需重新登录、重新创建密钥。

普通用户和所有业务 API Key 都不能调用管理接口，管理员会话也不能读取普通账户的业务内容。管理接口写入须携带同源 Origin 和原因，网页会自动发送。没有代登录、修改密码、发布、回滚、重启、恢复数据库、删除服务器文件、修改密钥或执行命令的入口。

AI 默认总并发为 8，报告、追问和预置生成共同使用上限。服务器通过 `BASKETBALL_ANALYST_CONCURRENCY_CAP` 指定可调整边界。默认管理修复预算每天 UTC 20 次视频重试、100 次实际 AI 请求，每个失败作业最多追加 3 次管理重试，批量最多 10 项。普通配额与管理修复预算分别计数，查询接口不触发清理或修复。

“备份状态未知”表示没有接入可验证的备份状态来源，不代表已有备份。服务启用状态反映应用配置，不能代替外部进程健康检查。发布、恢复和备份工具仍由服务器操作者执行。

## 已有账户如何升级

数据库迁移 `0012` 将已有账户设为普通用户，旧业务数据和结果保持原归属，不根据用户名自动提升管理员。全新空库才按服务器初始化配置创建管理员。`0013` 增加登记和同步字段，已提交历史任务按历史规则读取。

拆分旧 `admin` 账户使用显式服务器命令：

```sh
python scripts/migrate_admin_account.py \
  --database /absolute/offline/app.db --admin-identity admin --dry-run
```

命令以隐藏输入方式询问新的 `xue@dsb.com` 密码，默认只演练并回滚。所有写入方停止、队列及租约排空、数据库升级后，操作者才可将 `--dry-run` 改为 `--apply`。不要在命令行参数、聊天或 Git 中填写密码。

执行会将旧管理员的业务数据及关联迁移给普通账户 `xue@dsb.com`，保留内容，重建可核对的缓存和去重标识，撤销原业务密钥及旧会话，并将原账户设为管理员。目标身份冲突、活动队列或无法核对旧缓存来源时整体停止，不猜测、不覆盖。迁移后核对普通账户的任务、结果、档案、聊天及密钥，再由管理员重新登录。

本次只在隔离数据中验证命令，不执行生产账户迁移、备份或部署。
