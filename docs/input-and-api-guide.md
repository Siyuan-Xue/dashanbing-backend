# 登记、同步与 API 升级说明

网页和 API 使用同一套任务服务、账户状态、配额和结果生成规则。

## 创建与恢复任务

任务名和上传可以任意顺序填写，草稿保留已上传槽位、登记方式、人数、同步选帧和确认状态。提交前必须明确登记方式及 1–6 名参与者，并确认四路动作视频同步。

- 逐人出镜：参与者依次出现在注册视频中
- 多人并排：参与者一起并排出现在注册视频中

登记人数和有效面部、身体样本必须通过校验，不能忽略多出人员或缺失样本继续生成个人结果。失败后在任务详情点击修改输入，再确认返回草稿，修正配置或视频；原上传保留，已有完整报告的任务不能通过此入口覆盖。

## 确认视频同步

在四路视频中定位同一件共同可见的事，例如球落地的同一瞬间。可以播放、暂停、拖动、逐帧定位并选取同步帧，使用联动播放复核后确认。桌面同时显示四路，手机显示机位 3 和正在调整的机位。

机位 3 为参考，公共时间 = 本地时间 − 机位偏移。选帧时间为 `t1…t4` 时，机位偏移为 `ti − t3`，机位 3 始终为 0。确认后仅保存任务自己的数据，取消不保存临时选择。更换任意动作视频会使确认失效，即使文件内容相同也需重新确认；替换注册视频不影响四路同步。

首版支持恒定帧率、没有中途变速或剪接的素材，只校正常量偏移。服务端可以验证帧时间、范围和重叠区间，无法证明人为选取的两个事件是同一瞬间，也不能仅凭时间戳发现所有剪接。没有共同事件或有效重叠时不能确认。预览和帧图由独立缓存生成，保留原视频，按账户隔离。

文件标称 60fps 不代表每一帧都有固定间隔；掉帧或末尾时间戳跳变也可能返回 `unsupported_timeline`。2026-09-07 实测的原四组篮球样例存在这种情况，因此旧结果仍可查看，但当前原素材的预置重跑不能视为已验证可用。不能通过延长等待或重复提交消除此类输入错误，也不应把这些样例的旧成功记录当作新同步流程通过的证据。

## API 调用顺序

分步入口：

1. `POST /api/v1/tasks` 创建草稿，传入 `title`、`mode`、`analyst_locale`、`enrollment_mode`、`expected_persons`
2. `PUT /api/v1/tasks/{id}/inputs/{slot}` 上传注册视频和四路动作视频
3. `GET /api/v1/tasks/{id}/sync` 取得当前四路 `source_versions`
4. `PUT /api/v1/tasks/{id}/sync` 提交 `input_versions` 和四路选帧时间或偏移
5. `POST /api/v1/tasks/{id}/submit` 提交并轮询任务

同步 JSON 二选一，不同时发送：

```json
{
  "input_versions": {"cam_01":"version-1","cam_02":"version-2","cam_03":"version-3","cam_04":"version-4"},
  "selected_timestamps_ms": {"cam_01":1000,"cam_02":1100,"cam_03":900,"cam_04":950}
}
```

或以 `offsets_ms` 替换 `selected_timestamps_ms`，其中 `cam_03` 必须为 0。上述版本和时间仅为格式示例，必须使用自己的文件版本与真实对应事件。

需要可视化的客户端可调用 `POST/GET /tasks/{id}/sync/preview`，读取返回的预览视频 URL，再调用 `GET /tasks/{id}/sync/frames/{camera}?time_ms=…&source_version=…`。帧响应包含最近实际帧的时间、原始 PTS、帧编号及图像，不能把请求时间当成实际帧时间。

一次上传入口 `POST /api/v1/analyses/upload` 保留，multipart 同时发送五个文件、登记配置、`analyst_locale` 和 `sync` JSON。同步直接绑定本次上传版本，调用者不需要打开网页或弹窗。完整 Curl/Python 示例见网站 `/api/docs`，机器可读契约为根目录 `openapi.json`。

### 兼容性变化

保留原路由及响应字段，但新的提交必须补充人数和同步数据。创建不完整草稿仍可成功，提交缺少必要配置返回 422，视频替换导致原同步失效返回 409。历史已经提交的任务不被新增必填项追溯阻断，预置重跑使用样例自身核对过的并排登记、4 人及分组同步文件。

输入和同步失败返回 `detail.code`、`detail.message` 及必要字段；执行失败读取 `error_code`、`error_message`、`stage_message`。登记人数不符和样本不足有独立错误码，未知运行错误仍可记录为引擎失败，不能据此认定用户选择的视频错误。

当前账户额度读取 `/api/v1/account/usage` 和 `/api/v1/account/limits`，不能在客户端写死数值。停用、会话失效、密钥撤销和管理员边界对两套入口同时生效。

## AI 分析与训练档案

视频完成后按 `analyst_locale` 自动准备全场、各匿名球员及两种语气的报告集合，AI 失败不改写视频成功状态。`GET/POST /tasks/{id}/analyst/reports` 读取或补齐集合，单报告接口只刷新当前版本。没有 GLM Key 时明确显示未启用。

训练档案保存用户确认的球员或球队、目标、笔记及训练摘要。本场编号不会自动跨任务认人，需要在独立绑定弹窗中明确确认。绑定不重写本场分析；默认不对比，满足同档案、同模式、共同动作条件后，主动对比追加单独报告。API 的 context、training-profiles 和 comparisons 接口保持同样边界。
