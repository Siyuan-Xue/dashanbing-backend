## GPU 与 GLM 修复验证

源码通过已授权的 SCP 上传到独立验收目录，使用新的数据库、样例缓存和端口；原视频与模型只读复用，配置文件只读取 GLM Key，不修改生产代码或数据。首次修复包为 556,511 字节，SHA256 为 `28d03ec33e3a0cad18b81d06f9b6d9e3177b1d97dae628b4ef8ac8eb5d28c314`，后续最小补丁的文件指纹单列记录

GPU 为 RTX 4090，24,564 MiB 显存。根因是入口过早导入身份模块，缓存了默认模型与任务目录；调整导入时序后，严格模型加载及空帧推理通过。它只证明模型可以启动，不能代替真实视频结果准确性或吞吐验证

最终 v3 使用修复后的两类领取器和 180 秒 HTTP 观察窗口，四组样例的快速/完整共 8 次提交均返回 422 `unsupported_timeline`，耗时范围 19.63–70.02 秒，总计约 333.54 秒；这是输入检查耗时，不是 GPU 执行耗时。没有提交成功或可用任务运行时长、吞吐、峰值显存。同期独立账户限额读取返回 200，约 42ms，仅作为读请求可完成的旁证，不构成延迟保证。最终隔离服务收到 SIGINT 后正常关闭

预置 GLM 失败的根因已确认：71 位请求标识超过供应商允许的长度，直接使用已有 64 位作业摘要后恢复调用，模型、Key 和生成参数未变化。官方约束见[对话补全文档](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)

使用四组**已有真实输出**，独立生成中文全场与球员、两种语气共 40 个版本，39 个发布成功、1 个最终失败，总耗时 590.66 秒。共 62 次实际调用，41 次供应商成功响应、21 次限流，峰值并发 8，总用量 203,741 token；成功供应商响应等待 P50 45.81 秒、P95 100.90 秒、最长 118.63 秒

供应商成功响应不等于报告通过校验并发布。唯一最终失败版本先得到成功响应但未发布，后两次被限流；未保存首份未发布响应和具体异常，无法追溯其确切校验或写入原因。不把 41 次成功响应写成 41 份有效报告，不追加无限重试，不把最终失败改写为正常等待

本轮未取得新视频完成后自动生成整套报告的真实端到端证据，独立预置生成与离线自动队列测试分别标注。首轮 40 次上游错误、修复后部分失败和限流全部保留

## 隔离恢复

使用 12,288 字节的初始 SQLite 与 110,592 字节的合成文件，执行 8 次计划/快照/校验/恢复命令、一次合成版本变化以及旧版本回滚，12 项校验全部匹配，总计 0.23 秒。保留数据库完整性、外键、文件哈希、旧源未改动、新版本仍保留的证据

该时间只适用于小型离线合成数据，不是生产 RTO。回滚保留了旧快照内容，合成的新版本变化不进入旧快照；实际系统在快照之后可能发生的数据变化仍构成潜在丢失范围，本轮没有测量生产 RPO。账户迁移和作业恢复为隔离测试证据，没有执行生产迁移、生产备份或生产故障演练

## 据实确定的本版标准

1. 账户隔离、注册人数、同步版本、报告事实及账本校验仍按批准方案执行，实际异常不能靠降低标准变为通过
2. 功能通过仅限证据覆盖行为，失败、跳过、外部阻挡及未执行后续步骤分别记录
3. 页面和普通接口、GPU 与 AI 耗时均作同环境参考，不设统一性能否决线，不承诺 20 人同时在线分析
4. 视频单任务观察窗口为 2 小时；完整视频检查的提交请求可观察 180 秒，普通接口 30 秒。观察超时只说明未观察到完成，不直接判定数据错误，也不算成功
5. 继续使用现有 GLM 并发、有限重试及供应商退避，不通过新增性能逻辑达到验收数字
6. 恢复仅认可隔离合成演练的哈希、完整性和回滚，不声称生产恢复时间或零数据损失
7. 按授权保留已知问题后合并推送，不另设全测试通过门槛，不绕过仓库保护
