## 实现交付

- 独立管理员后台：概览、用户管理、调度、配额与并发、只读运行状态、操作审计
- 普通用户与管理员互斥，业务密钥不能调用管理接口，管理员不读取视频、报告正文、聊天与训练备注
- 管理操作要求原因，账户启停、会话撤销、配额调整、暂停领取、优先级、有限重试和补齐均受服务端边界控制
- 注册方式与 1–6 人验证、四机位同步预览和选帧、上传版本失效、草稿恢复及返回输入修正
- 分步任务与一次上传 API 共用注册、同步、语言、权限、配额及队列规则，更新 OpenAPI、类型和 Curl/Python 文档
- 管理员账户迁移脚本、数据库迁移、隔离恢复与测量脚本

操作范围和兼容性变化见 [管理员指南](admin-guide.md)、[输入与 API 指南](input-and-api-guide.md)、[恢复流程](recovery-workflow.md)

## GPU 与 GLM

经用户明确授权，将 556,381 字节的源码包通过 SCP 上传到独立目录，SHA256 为 `34cc16b10d3faf3a9688fd44e68501d4e62c3bc1193c7c4ab673476ebaafede8`。使用新的数据库、样例缓存和端口，现有视频及模型只读复用，配置文件只读取服务端 GLM Key，不修改生产代码或数据

GPU 为 RTX 4090，24,564 MiB 显存。权重文件、样例、FFmpeg、CUDA 和剩余存储检查通过，严格空帧推理在 OSNet 加载处失败，队列按设计保持停止。计划的 quick-demo、mixed-actions、verified-outcome、layup-demo 各快速/完整一遍共八项均未提交，因此没有本轮注册正确率、同步准确性、动作归属、GPU 耗时、吞吐或峰值显存数据。末尾 GPU 快照不是任务峰值

AI 作为独立测量，使用上述四组**已有真实输出**生成中文全场与四位匿名球员、两种语气的预置报告，共 40 项。40 次实际供应商调用全部返回 `upstream_error`，全部作业失败，每项实际调用 1 次，最高重叠调用数为 8

包含失败的供应商/网络等待中位数为 0.43 秒、P95 为 5.38 秒；作业入队到首次调用中位数为 0.61 秒、P95 为 4.91 秒。这些是失败请求的测量值，**不能当作成功报告延迟**。未取得成功首份/整套报告时间、可信 token 用量或本次视频完成后的自动报告链路证据

计时器仅保留上游错误类别，未保存具体 HTTP 状态或供应商响应正文，本轮无法进一步判定账户、模型或参数等哪一项导致拒绝，不推测为限流或余额不足。限流等待、流式追问及异常 JSON 的本轮真实成功链路未验证，离线测试单列保留

## 隔离恢复

使用 12,288 字节的初始 SQLite 与 110,592 字节的合成文件，执行 8 次计划/快照/校验/恢复命令、一次合成版本变化以及旧版本回滚，12 项校验全部匹配，总计 0.23 秒。保留数据库完整性、外键、文件哈希、旧源未改动、新版本仍保留的证据

该时间只适用于小型离线合成数据，不是生产 RTO。回滚保留了旧快照内容，合成的新版本变化不进入旧快照；实际系统在快照之后可能发生的数据变化仍构成潜在丢失范围，本轮没有测量生产 RPO。账户迁移和作业恢复为隔离测试证据，没有执行生产迁移、生产备份或生产故障演练

1. 功能与权限期望仍采用批准的方案，不因发现异常而放宽账户隔离、人数验证、同步一致性或报告事实要求

6. 按用户授权保留缺陷后合并推送，本轮不另设“所有测试通过”的合并条件，也不绕过仓库保护
