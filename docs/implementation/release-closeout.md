# 功能补齐与收尾实施记录

本轮基于 `5141dc9`，对应用户确认的管理员、注册与同步、API 对齐及流程验收计划

## 交付约束

- 普通用户与管理员互斥，管理员只管理账户和调度元数据
- 管理员界面不提供部署、重启、恢复、删除文件或读取业务内容的能力
- 网页和 API 共用注册、人数、同步、语言、权限、配额与报告生成规则
- 注册支持逐人和并排，1–6 人；同步使用四机位同一事件选帧，以 cam_03 为参考
- 上传版本绑定同步快照，动作视频替换后重新确认，草稿可恢复
- 测试是测量与记录流程，不预设容量/耗时通过线，不追加集中验收后的优化循环，不伪造通过
- 20 用户是测量负载；Chrome、真实 macOS Safari 与 iPhone Safari 分别记录
- 恢复只实现脚本和隔离测试，不备份生产数据、不建立定时任务
- 完成后推送功能分支并合入 main，不执行生产迁移或部署
- 凭据、私有视频、生产数据库和用户聊天文件不进入 Git

## 分工与整合顺序

1. 共享模型及接口契约
2. 管理员后端、前端，注册同步后端、前端，恢复/测量工具
3. OpenAPI、示例文档和跨模块整合
4. 集中测试、测量、单轮审查，记录缺陷与未执行项
5. Git 合并推送与最终证据索引

## 接口边界检查

| 交接 | 约定 |
| --- | --- |
| 管理后端 → 管理前端 | 专用 DTO，不复用含业务正文的任务接口 |
| 注册同步后端 → 同步前端 | 预览、实际帧时间、同步 GET/PUT、草稿状态与输入版本 |
| 共享模型 → 两套任务入口 | 登记方式、人数、语言和同步快照，父任务统一整合 |
| 恢复工具 → 运行数据 | 明确输入/输出，隔离测试，禁止隐式生产路径 |
| 测试 → 交付 | 保留原始结果与失败，能力标准根据结果整理 |

实施阶段允许必要调试；集中验收开始后仅记录发现，不启动验收优化循环
